# ConsoleModbus

Пример Modbus TCP на .NET: сервер (симулятор ПЛК) и клиент.

## Что изменено

### Разделение ответственности 50/50
- **Coils 0..4** изменяет **Клиент**.
- **Coils 5..9** изменяет **Сервер**.
- **Holding Registers 0..9** изменяет **Клиент**.
- **Holding Registers 10..19** изменяет **Сервер**.

Это позволяет одновременно видеть работу Master и Slave без коллизий записи.

## Маркировка источника изменений

В консольном выводе клиента добавлены пометки владельца:
- `[CLIENT]` — адреса, которыми управляет клиент.
- `[SERVER]` — адреса, которыми управляет сервер.
- `[MIXED]` — типизированный блок, который затрагивает границу диапазонов (например `STRING[4-6]`).

## Поведение приложений

### Server
- Запускается на `127.0.0.1:502` (UnitId=1).
- В цикле обновляет только свою половину:
  - `Coils[5..9]` (циклическое ON/OFF)
  - `Registers[10..19]` (DATE, DWORD, дополнительные INT)

### Client
- Подключается к серверу `127.0.0.1:502`.
- В каждой итерации:
  1. Записывает свою половину (`Coils[0..4]`, `Registers[0..9]`).
  2. Читает все `Coils[0..9]` и `Registers[0..19]`.
  3. Показывает данные с маркировкой источника.

## Запуск

```bash
# Терминал 1
cd Server
dotnet run

# Терминал 2
cd Client
dotnet run
```

## Проверка корректности

- Клиент меняет только `Coils[0..4]` и `Registers[0..9]`.
- Сервер меняет только `Coils[5..9]` и `Registers[10..19]`.
- В клиентском выводе видно разграничение по меткам `[CLIENT]` и `[SERVER]`.
